# 部署 XOps

> 一个进程 · 两个监听口 · 一个 sqlite 文件。
> **难的不是把它跑起来，是把它该由你建的那道墙建起来。**

这份文档回答三件事：**怎么跑起来** · **哪些事平台不做而你必须做** · **出事了看哪里**。

⚠️ **第二件是重点。** XOps 明写了一批"我们不做"的决定（容器隔离 `D62`、资源硬上限 `D64`、
限流 `D48`），它们**不是待办，是转交**——责任转移，不是消失。
一个把这份文档只读到第一节的部署，跑得起来，也真的没有那道墙。

---

## 1. 跑起来

```bash
# ① 一把加密密钥。**它没有默认值**，装配会拒绝起来。
export XOPS_SECRET_KEY=$(xopsd --generate-key | cut -d= -f2)

# ② 一个库文件（不给就是 :memory:，进程退出数据就没了）
export XOPS_DB=/var/lib/xops/xops.db

# ③ 一个能登进 Web 的账号（不给的话页面在、路由在，就是没人进得去）
export XOPS_LOGIN='alice:换掉这个口令:Alice'

# ④ 模型凭据（不给就是桩引擎：跑得通，什么也没真跑）
export XOPS_MODEL_KEY=sk-...

# 第一把 MCP 令牌只能从命令行来 —— 签令牌本身要令牌，第一把无处可来
xopsd --issue-token alice

xopsd
```

`xopsd --check` 装配一遍、打印横幅、**不监听任何端口**。上线前先跑它。

### 全部环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `XOPS_SECRET_KEY` | **无，必填** | 只读仓凭据与插件配置的加密密钥（32 字节十六进制）。⚠️ **这里不给默认值是刻意的**：一个写死的默认密钥**看起来是加密的，实际不是**——那比没有密钥更糟 |
| `XOPS_DB` | `:memory:` | 库文件路径。⚠️ 默认值是内存库，**进程退出数据就没了** |
| `XOPS_MCP_ADDR` | `127.0.0.1:8765` | MCP 写入面 |
| `XOPS_WEB_ADDR` | `127.0.0.1:8766` | 只读 Web 面 |
| `XOPS_LOGIN` | 无 | 预置账号，`账号:口令[:显示名]`，逗号分隔多个 |
| `XOPS_MODEL_KEY` | 无 | 模型凭据。**不给就跑桩引擎** |
| `XOPS_MODEL` | `claude-sonnet-4-6` | 默认模型 |
| `XOPS_MODEL_BASE_URL` | 官方 | 兼容 Anthropic Messages 的任何一个。⚠️ **末尾那个斜杠不是可有可无的**——`Url::join` 在 base 不以 `/` 结尾时会**替换掉最后一段**，症状是一个查不出原因的 404 |
| `XOPS_WORKSPACES` | 临时目录 | 只读工作区的根 |
| `XOPS_ASSETS` | 嵌进二进制的那份 | 前端产物目录。开发时才用 |
| `XOPS_LOG` | `info` | `off`/`error`/`warn`/`info`/`debug`。⚠️ 不认识的值当 `info`，**不当 `off`**——一个拼错的变量把日志静默关掉是最坏的那种 |

### 两个口分开，是结构性的

MCP 写入面与只读 Web 面**各监听各的端口**。这不是为了好看：
`xops-web` 里**结构性地不存在写业务对象的路由**，而那件事只有在两个面分开时才成立
（`G2`、`I-L`）。⚠️ **不要把它们放到同一个反向代理路径下再按前缀转发**——
那样一次配置失误就把两个面合成一个。

`/healthz` 在 Web 面上：**不认证、不查库、回话里没有任何信息**。给编排器用。

### 单实例

⚠️ **表级写串行是在应用层用进程内的锁做的，只在单实例下成立**（`D46`）。
起第二个进程指向同一个库，**串行这条规则当场不成立**，而它不会报错。
要多实例得先有一把进程外的锁 —— 那是一个还没做的决定。

## 2. 平台不做、你必须做的

启动横幅上会印两张表，**它们要一起读**：

```
⚠️  裸跑（D58）：以下 7 条没有兑现 ……      ← 缺什么
  实际拦着的（D64）——                     ← 有什么在拦着
```

⚠️ **只看第一张会以为它完全敞着；只看第二张就是在假装那 7 条做完了。**

### ① 隔离：没有容器（`D62`）

执行**直接在宿主上发生**。技能跑起来的那个 agent 与 `xopsd` 是同一个进程。
没兑现的逐条在横幅上，其中要紧的是：

- **两次执行共用宿主文件系统，互相看得见**（`EXE-009`）
- **对外网络不是默认拒绝**——技能声明的网络白名单**只被记录，没有被强制**（`EXE-007`）
- **没有东西可销毁**，残留由执行方自己收拾（`EXE-011`）

**平台这一侧兑现的边界**（都可跑可测，不靠容器）：

```text
工具集只有 Read / Glob / Grep / EmitRow    没有 shell，写不了文件，派不了子代理
路径锁在只读工作区里                        没声明代码仓就一个文件都不准碰
派工单不含凭据，也不含到 XOps 的网络路径     执行方拿不到令牌，也没有路可走
唯一的写向是 EmitRow，只通向已声明的表
```

**你该建的**：把 `xopsd` 放进容器、或一台专用机器。⚠️ 判据很简单——
**这台机器上还有什么是你不希望一个模型生成的技能读到的**。
如果答案不是"没有"，那道墙还不够。

### ② 资源上限：硬的那一半在你这边（`D64`）

**没有 OS 级的 CPU / 内存 / 磁盘上限**，超限不会被内核终止。
⚠️ 在进程内做不到：`setrlimit` 是**进程级**的（会把 `xopsd` 自己一起限住），
cgroups 要 Linux 加权限，两者粒度都不是"一次执行"。

**平台这一侧拦着的六道**（都可测，横幅上逐条印出来）：

| | |
|---|---|
| `TSK-005` | 单次 token 上限：引擎每次模型调用后比一次，**撞上就在半路结束回合** |
| `EXE-019` | 看门狗超时：挂住不动的执行被强制终止 |
| `EXE-027` | 并发上限：平台 16 · 项目 4 |
| 上游 | 工具回话有界：Grep 1 MB · Glob 1000 项 · 工具结果 50 KB / 合计 500 KB |
| `EXE-025` | 产物落表时截断并明确标注 |
| `EXE-031` | 产出行一次最多 500 行 |

⚠️ **剩下的是一个上界，不是一道墙**：16 × 单次执行的峰值内存。
没有硬上限的正是那个"峰值"，它现在由 token 预算间接约束。
**一个恶意或病态的技能仍然可能把这台机器拖垮。**

**你该建的**（任选其一，从上到下由强到弱）：

```bash
# systemd —— 最省事的一档
[Service]
MemoryMax=4G
CPUQuota=200%
TasksMax=512

# 或者 docker
docker run --memory=4g --cpus=2 --pids-limit=512 …
```

⚠️ **不要只设 `MemoryMax` 就当作完事**：撞上它 `xopsd` 会被 OOM killer 干掉，
而 `D61` 明写着 **abort / OOM 会把在途执行一起带走，那时没有活着的进程去归类**
（`EXE-017` 只兑现了一半）。所以内存上限要配**自动重启**，
并且知道重启之后那些执行停在 `running` 上。

### ③ 限流：不做（`D48`）

平台**不提供**按用户或按 tool 的限流。挡住重复调用的是别的机制
（`MCP-006` 幂等键、`TRG-013` webhook 按事件标识幂等、`TSK-008` 重叠策略），
挡成本失控的是单次 token 上限与并发上限。

**剩下的"高频但各不相同的调用"是你的事** —— 交给 `xopsd` 前面的反向代理。
⚠️ 这是**明写的不做，不是"以后再说"**。

### ④ 登录：只有预置账号（`IDN-002` 的一半）

`XOPS_LOGIN` 是**部署自测**那一半：口令存的是 SHA-256 摘要，
**没加盐、没有慢哈希，也不打算有**。真正的登录路径是 OAuth，**那一半还没接**。

⚠️ 所以：**不要把 Web 面直接暴露在公网上**，也不要拿它当一个面向终端用户的口令体系。

### ⑤ TLS：不做

两个面都是明文 HTTP。⚠️ **Web 会话 cookie 与 MCP 令牌都在明文里走** ——
放一个终止 TLS 的反向代理在前面，或者只监听回环并用 SSH 隧道。

## 3. 数据

### 库

一个 sqlite 文件，**WAL 模式**（建库时定一次）。所以备份要带上同目录的
`-wal` 与 `-shm`，或者用 `sqlite3 xops.db ".backup out.db"`。
⚠️ **直接 `cp` 一个正在写的库会拿到一份撕裂的快照。**

### 工作区

`XOPS_WORKSPACES` 下面是只读的代码仓副本。它们**可以随时整个删掉**——
下一次执行会重新备。⚠️ **但不要在有执行在跑的时候删**。

### 保留期

平台自己跑三条清理作业（每小时一次）：执行产物、审计、`_notices`（默认三个月）。
⚠️ **它们整批按时间进行，没有"删掉某一行"的入口**（`RET-005`）——
要清理个别数据，只能从业务那一侧删行。

### 换库

存储层**只用基本增删改查，不依赖任何数据库特有能力**（`D46`），所以库是可换的。
⚠️ **可换的是库，不可换的是"表级写串行"这条规则** —— 换到一个多写者的库上，
串行还得由应用层保证。

## 4. 出事了看哪里

**先看启动横幅。** 它印的每一条都是"**不能悄悄发生的降级**"：

| 横幅上说 | 意思 |
|---|---|
| `执行引擎是**桩**` | 没设 `XOPS_MODEL_KEY`。⚠️ **跑得通，什么也没真跑**——查起来很慢的一种错 |
| `没有预置任何账号` | 没设 `XOPS_LOGIN`。页面在、路由在，**登录一律回「凭证不对」** |
| `裸跑（D58）：以下 7 条` | 见 §2 ①。**这张表不会因为我们做点什么而缩短** |
| `实际拦着的（D64）` | 见 §2 ②。**它与上一张要一起读** |
| `插件的出网后端没接` | 声明了出网的插件也发不出去 |

**然后看 `_runs`。** 每一次执行都在那张表上：状态、失败分类、用量与上限、
产出、过程记录。⚠️ **失败分类是有意义的**——`token-budget` 与 `model-service`
要采取的行动完全不同（前者调 `tokenBudget`，后者重跑）。

**日志**走 stderr，`XOPS_LOG=debug` 更细。⚠️ 令牌与凭据**不进日志、
不进过程记录、不进派工单**（`I-F`）——如果你在任何一处看到了凭据原文，那是缺陷，请报。

### 几条会被误判成"平台坏了"的

- **看板上一行都没有** —— 先确认那张表建过看板。⚠️ 没建看板的表在页面上是有的
  （表清单里），但看不到行：看板 = 一张表的一个视图，没有视图就没有行。
- **技能读到了错的东西** —— 确认它声明了代码仓。⚠️ **没声明代码仓的技能
  一个文件都读不到**，那是设计如此（`I-I`），不是路径配错了。
- **执行成功但产出是空的** —— 看 `_runs.trace`。多半是技能在找一个它没有的工具
  （没有 shell、写不了文件、派不了子代理）。
- **任务突然开始报 `token-budget`** —— 单次 token 上限是**真的在比**的。
  把 `tokenBudget` 调大，不要把判定关掉。

## 5. 升级

```bash
git pull && git submodule update --init --recursive   # ⚠️ 子模块必须一起更
cd web && npm ci && npm run build                      # ⚠️ 必须在 cargo build 之前
cd .. && cargo build --release -p xopsd
```

⚠️ **前端要先构建。** `web/dist` 在**编译期**被嵌进二进制（`D55`：部署方不需要 Node），
顺序反了的话 `assets.rs` 只打一条 warning 就过去 —— **二进制里没有页面，
而没有任何一处会失败**。`xopsd --check` 之后看横幅有没有页面那一段。

⚠️ **子模块不更的话编译会失败**（`vendor/attacore` 是 path 依赖）—— 这一条是好的失败方式。

数据库**没有迁移脚本**：schema 变化由契约治理盯着（`docs/contracts/data.md`），
真要改的那天会在发布说明里写清楚。
