# RP-02 身份、项目与审计

> 身份提供方 · 令牌 · 项目与成员 · 权限判定 · 追加式审计

## 归属与依赖

- **依赖**：RP-01 存储与写串行。
- **被依赖**：RP-03 MCP 基座（认证与鉴权来自这里）、RP-08 Git 仓绑定，以及其余全部包的归属判定。
- **里程碑**：M1。
- **独立性**：做完这个包，平台是一个可登录、可建项目、可拉人、有完整审计的骨架——**但它还没有操作面**（MCP 在 RP-03）。本包的验收经内部接口进行。

## Crate 归属

| crate | 本包是否新建 | 对外只经什么被用 |
|---|---|---|
| `xops-identity` | **新建** | 身份解析（令牌 → 用户）· 项目与成员的读写 · **权限判定纯函数** |
| `xops-audit` | **新建** | 追加一条审计事件 · 查询事件流 · 按对象查历史 |

**本包用 RP-01 的存储契约与串行执行器，不直接触碰 SQLite。**

## 背景与价值

这个包把**身份、归属与留痕**这三样不可避免的共享地基收在一起。三者互为前提：

- **身份**要用**项目角色**来判断能做什么；
- **项目与成员**的每一次变更都要交给**审计**；
- **审计**的行为人来自身份解析。

守住的核心性质只有一条：

> **每一条记录都能回答"谁做的"，而这个答案由凭据给出，不由调用方自述。**

MCP 协议本身不认证调用者——管道那头的 agent 说自己是谁没有任何约束力。这里松了，后面所有东西都是装饰。

**还有一条形状很小、后果很大的**：`PRJ` 域要求**非项目成员看不到项目的存在**——查询一个自己不是成员的项目，响应与查询一个真正不存在的项目**完全一致**。否则错误码本身就成了探测他人项目的工具。

> ⚠️ **上一版这些条目与 MCP 基座在同一个包里（十二包版的 RP-01「平台基座」，52 条）。本版把 MCP 拆走了**，理由是它们在 Rust 工程里是两个 crate：一个是领域与判定，一个是协议与注册骨架。**代价是本包做完之后没有对外操作面**，验收要靠内部接口——这笔账在 README §2 里认过。

## 范围

### 包含

- 身份提供方接口（预置账号 + GitHub OAuth）、自注册开关、用户模型
- 访问令牌的签发、撤销、过期、解析
- 项目的创建与归档、成员与角色、**权限判定（纯函数）**
- 非成员不可见：无权限与不存在返回**完全一致**的响应
- 追加式审计事件与它的查询、重建、保留期

### 明确不包含

- **MCP server 的服务形态、认证中间件、tool 注册骨架**——归 RP-03。本包提供"令牌 → 身份"与"身份 + 项目 → 能不能做"两个纯函数，**不知道调用它们的是 MCP 还是别的什么**。
- **Web 会话**——归 RP-05。会话凭据与 MCP 令牌互不通用（`I-L`）是那个包的事。
- **任何业务对象**——表、技能、任务、执行、插件、流程各归其包。
- **模型凭据与代码仓凭据**——分别归 RP-07 与 RP-08。本包的令牌只用于"调用者认证到 XOps"。

本包认领 [`requirements.md`](requirements.md) 的 **37 条**。**条目正文以 `requirements.md` 为准**，下表只是索引与一句话摘要。

### PRJ 项目与成员（12 条）

| ID | 摘要 |
|---|---|
| `PRJ-001` | 任何用户都可以创建项目，无需申请或审批。 |
| `PRJ-002` | 项目有稳定的、创建后不可变的标识；显示名可变，且不得作为关联键使用。 |
| `PRJ-003` | 项目另有一个短名：全平台唯一、创建后不可变、限定为便于手写的字符集。 |
| `PRJ-004` | 项目内恰好三个角色：所有者（管理成员与项目本身、写受保护表、写插件配置）、维护者（管理项目内业务对象、安装插件）、成员（建表、写表、写技能与任务、参与流程）… |
| `PRJ-005` | 所有者可把其他用户加入项目并指定角色、变更角色、移除成员。 |
| `PRJ-006` | 一个项目必须始终至少有一个所有者。 |
| `PRJ-007` | 同一用户在不同项目中的角色互相独立。 |
| `PRJ-008` | 非项目成员看不到项目的存在。 |
| `PRJ-009` | 项目可被归档。 |
| `PRJ-010` | 权限判定是确定性纯函数：相同的（用户，项目，动作）在角色未变时永远得到相同结果，不受任何模型或外部服务影响（G8）。 |
| `PRJ-011` | 项目角色不得由受治理路径之外的任何自动化改变——特别地，执行中的任务不得提升自己或他人的角色。 |
| `PRJ-012` | 每个对象恰好有一个归属方：项目（公共技能、公共任务、表、流程、插件、模板实例）或用户（私有技能、私有任务）。 |

### IDN 身份（7 条）

| ID | 摘要 |
|---|---|
| `IDN-001` | 全部登录经同一个身份提供方接口完成。 |
| `IDN-002` | 身份提供方至少包含：预置账号（部署自测用）与第三方 Git 平台 OAuth（先做 GitHub）。 |
| `IDN-003` | 不开放自注册。 |
| `IDN-004` | 用户是平台的顶层主体，用户之间地位平等，不存在任何上下级或分组关系。 |
| `IDN-005` | 每个用户有稳定的、创建后不可变的用户标识；显示名与邮箱可变，不得作为关联键使用。 |
| `IDN-006` | 用户记录保存其来源身份提供方与在该平台上的账号标识，使"XOps 里的这个人"与"代码仓里提交的那个人"能够对上。 |
| `IDN-007` | OAuth 登录回调是 G1 的两个非 MCP 入口之一，它只能做一件事：完成身份验证、建立会话。 |

### TOK 令牌（7 条）

| ID | 摘要 |
|---|---|
| `TOK-001` | 令牌一律按人签发，不存在按服务、按项目或按团队共享的令牌。 |
| `TOK-002` | 令牌签发时只呈现一次，之后系统只保存不可逆摘要，任何位置都无法再次读出原文（I-A）。 |
| `TOK-003` | 令牌可被其所有者随时撤销，撤销后立即失效，无生效延迟窗口。 |
| `TOK-004` | 令牌可设过期时间；已过期与已撤销的行为完全一致。 |
| `TOK-005` | 令牌解析失败（不存在、已撤销、已过期、格式非法）时，错误不得泄露具体原因，也不得泄露该令牌是否曾经存在。 |
| `TOK-006` | 每个令牌记录最后一次成功使用的时间，供所有者识别不再使用的令牌。 |
| `TOK-007` | 行为人一律由令牌解析得出。 |

### AUD 审计（11 条）

| ID | 摘要 |
|---|---|
| `AUD-001` | 事件日志只追加。 |
| `AUD-002` | 每条事件至少包含：稳定事件标识、发生时间、行为人、所属项目、事件类型、目标对象标识、结构化载荷。 |
| `AUD-003` | 事件按所属项目分区，非成员查询不到该项目的任何事件。 |
| `AUD-004` | 对任意给定时刻，可以仅凭事件流重建当时的业务状态快照，不依赖任何当前视图。 |
| `AUD-005` | 事件写入与其对应的业务副作用在同一次操作中完成——不存在"业务成功但没留痕"或"留了痕但业务没生效"的中间态。 |
| `AUD-006` | 事件的写入路径不经过任何模型（G8）。 |
| `AUD-007` | 失败的 MCP 调用也留痕，但与成功事件区分——失败留痕用于排查与滥用检测，不进入业务账本。 |
| `AUD-008` | 支持按项目、时间范围、事件类型、行为人、目标对象查询；并支持查询某个对象的完整历史。 |
| `AUD-009` | 事件类型有统一目录与扩展方式。 |
| `AUD-010` | 审计事件流的保留期可配置，保留期内不可删除，到期清理只能整批按时间进行，不得选择性删除个别事件。 |
| `AUD-011` | 以下动作一律留痕，缺一条就有一处黑箱：项目与成员变更 · 建表与加列 · 仓绑定与凭据轮换 · 技能发布 · 任务启停 · 每次触发（含被拒绝与被跳过的）·… |

## 关键不变量

`I-B`（`writtenBy` 来自令牌解析，不来自请求体）· `I-C`（每个对象恰好有一个归属方）· `I-D`（事件不可变、可查完整历史）· `G4`（权限一律按项目判定，无跨项目全局角色）· `G5`（身份来自凭据）。

## 接口面

**本包不直接暴露 MCP tool**——tool 由 RP-03 注册，语义在本包。涉及的意图：查询当前身份 · 创建项目 · 查询我参与的项目 · 查询项目详情 · 加成员 / 改角色 / 移除 · 归档项目 · 令牌的签发与撤销 · 查询项目事件流 · 查询某对象完整历史。

**对内提供**：

```text
resolve(token)              -> 身份 | 无效     —— 唯一的身份来源
can(actor, project, action) -> bool           —— 纯函数，无 I/O
audit.append(event)         -> ()             —— 与业务写同一原子边界
```

## 验收标准

- **令牌是唯一身份来源**：请求体里放 `actor` / `user` / `author`，一律被**静默忽略**，写入的行仍归属令牌持有人。
- **非成员探测**：查询一个自己不是成员的项目，与查询一个真正不存在的项目，**响应逐字节一致**（含错误码、消息、耗时不构成侧信道）。
- **令牌一律按人签发**：不存在"项目令牌""服务令牌"这类无人归属的凭据（这条是 `XFG` 职责分离的前提）。
- **撤销即刻生效**；过期令牌解析失败。
- **权限判定是纯函数**：给定 (身份, 项目, 动作) 三元组，不读库、可单测穷举。
- **审计与业务写同一原子边界**：构造一次业务写失败，**审计事件也不存在**；反之亦然。
- **审计可重建**：从事件流重建出当前的项目、成员、角色状态。
- **归档项目转为只读**（`PRJ-009`）——⚠️ 在途实例与在途执行怎么办是 **Q23**，本包按"新写入被拒绝"实现，在途的处置留到 RP-14。

## 内部工作包建议

一次 **Major Change**：

```text
WP-A 身份与令牌（提供方接口、预置账号、签发/撤销/解析）
        │
        ▼
WP-B 项目与成员与权限判定（纯函数、非成员不可见）
        │
        ▼
WP-C 审计（追加、同原子边界、多维查询、重建、保留期）
```

**WP-B 的"非成员不可见"要在这一步就做对。** 它不是一个可以事后加的过滤器——它要求每一条查询路径**从一开始就以成员身份为前提**去构造，而不是查完再筛。

## 风险与待定

- **GitHub OAuth 提供方是外部依赖**，`IDN-001` 与 `IDN-007`（回调）要留出联调时间。预置账号先行，OAuth 不阻塞本包其余部分。
- **Q23（归档与在途实例/在途执行）**在本包只能做一半。**另一半必须在 RP-14 关掉**，不要让它悬着——一个归档了但流程还在跑的项目，是一个没人负责的状态。
- **审计的保留期（`AUD-009`）与任务输出的保留期（RP-12 的 `RET-*`）是两条并存的规则，互不取代。** 实现时不要合并成一套——它们挂在不同的东西上（一个全局、一个挂在任务上）。
