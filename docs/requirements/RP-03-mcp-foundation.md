# RP-03 MCP 基座

> 唯一操作面 · 窄接口纪律 · 注册骨架 · 幂等 · 错误契约 · 能力发现

## 归属与依赖

- **依赖**：RP-02 身份、项目与审计（认证与鉴权的语义来自它）。
- **被依赖**：其余全部要暴露 tool 的包——RP-04、RP-08、RP-09、RP-10、RP-11、RP-14、RP-15、RP-16、RP-17、RP-18、RP-19。
- **里程碑**：M1。
- **独立性**：做完这个包，存在一个可被 agent 连上的 MCP server：能认证、能发现能力、能把调用路由到已注册的 tool、每次写入都幂等且留痕。**它自己不提供任何业务 tool**——用一两个测试用 tool 就能完整验收。

## Crate 归属

| crate | 本包是否新建 | 对外只经什么被用 |
|---|---|---|
| `xops-mcp` | **新建** | `ToolRegistry`（注册一个 tool 需要交出什么）· server 的服务形态与生命周期 |

**其余包只做一件事：把自己的 tool 注册进来。** 它们不改本 crate——这是本包能被八个包共用而不打架的前提。

## 背景与价值

**MCP 是唯一操作面**（P3、G1）。这个包定的不是某几个 tool，是**每一个 tool 都必须满足的那套纪律**：

```text
固定形状 schema           未在 schema 中声明的字段一律拒绝，不静默丢弃
不提供任何通用透传 tool     没有"把这段上下文一起发过去"这种口子
身份只来自令牌            参数里的 actor / user / author 一律被静默忽略
写操作幂等                带幂等键的重复调用不产生第二次副作用
无权限与不存在返回相同错误  否则错误码就是探测工具
```

> **"任意表 CRUD"怎么不违反这条**：每张表建好之后，平台为它**派发一组专属的读写 tool**，各自带由该表 schema 生成的固定形状输入 schema。**不存在一个 `{table, values: 任意形状}` 的通用写 tool。** 派发机制的实现在 RP-04，但**它必须落在本包给出的注册骨架上**——否则那套纪律就有了一个例外，而一个例外就够了。

**这个包的价值全在"骨架"两个字上**：认证、鉴权、schema 校验、幂等、留痕这五件事，要么在注册的那一刻被一次性固化下来，要么就得在每一个 tool 里各写一遍。**后者等于把纪律交给自觉。**

### 四个非 MCP 例外，一次说清

`MCP-013` 列的四个例外，每一个都被削得只剩一件事可做：

```text
OAuth 登录回调    完成身份验证、建立会话。不能创建或修改任何业务对象
Git webhook 端点  产生一个 git 事件。不能创建或修改任何对象（端点实现在 RP-13）
会话面            Web 登录/登出。不能用于任何写操作（I-L，实现在 RP-05）
令牌管理面        签发与撤销令牌本身（实现在 RP-02）
```

**本包的责任是把这四个例外写死成一张清单，并让"第五个例外"在评审时必须被论证。**

## 范围

### 包含

- MCP server 的服务形态、传输、生命周期
- **认证**：令牌解析（调用 RP-02），身份不来自请求体
- **tool 注册骨架**：注册一个 tool 时必须交出的东西（固定形状 schema、需要的角色、是否幂等、留痕形状）
- **schema 校验**：未声明字段一律拒绝，不静默丢弃
- **幂等**：幂等键的语义与去重
- **错误契约**：无权限与不存在返回相同错误
- **能力发现**：按调用者角色裁剪可见的 tool
- 四个非 MCP 例外的清单与边界

### 明确不包含

- **表专属 tool 的派发机制**（`MCP-005`）——机制归 RP-04，**本包只提供它必须落在其上的注册骨架**。
- **任何具体的业务 tool**——各归其包。
- **Web 的只读 HTTP 面**——归 RP-05。**两者不是同一个服务面**，不要共用路由层。
- **速率限制**——不做（`MCP-015`，D48）。

## 关键不变量

`G1`（所有写操作经 MCP，四个例外各只能做一件事）· `G5`（身份来自凭据）· `I-B`（`writtenBy` 不来自请求体）。

## 接口面

**对外**：MCP server 本身，以及身份域的三个 tool（查询当前身份 · 能力发现 · **查询我待处理的流程节点**——后者的实现在 RP-14，**注册位在这里**）。

**对内提供给其余八个包**：

```text
registry.register(tool) —— 注册时必须交出：
    固定形状的输入 schema（不接受"任意对象"）
    需要的角色
    是否幂等 + 幂等键从哪来
    留痕形状
—— 交不出这几样的 tool 注册不进来。这是纪律的落点，不是文档里的一句话
```

**契约元素**（基线在 [`../contracts/`](../contracts/README.md)，正文由本包自己的变更逐条添加）：

```text
api:mcp.registry.*                  tool 注册接口面（MCP-012）：schema · 角色 · 幂等 · 留痕
api:mcp.error.*                     统一错误契约（MCP-007）；**无权限与不存在是同一条**（MCP-008）
api:mcp.tool.identity.*             查询当前身份 · 能力发现 · 我待处理的流程节点（实现在 RP-14）
rust:xops-mcp#*
```

> **窄接口纪律（MCP-004）在契约层的兑现**：注册进来的每一个 tool 都要有一份固定形状的
> 输入 schema 落在 `contracts/api/mcp/*.json`。交不出 schema 的 tool 登记不进基线。

## 验收标准

- **未声明字段**：请求里多带一个 schema 里没有的字段，**被拒绝**，不是被静默丢弃。
- **不存在通用透传 tool**：枚举全部已注册 tool，**没有任何一个接受"任意对象"形状的输入**。
- **身份不来自请求体**：参数里放 `actor` / `user`，被静默忽略。
- **幂等**：同一幂等键重复调用，**不产生第二次副作用**，且返回一致。
- **错误契约**：无权限与不存在，**响应逐字节一致**。
- **能力发现按角色裁剪**：成员与所有者看到的 tool 清单不同，且看不到的那些**调用也失败**（裁剪不是只藏起来）。
- **四个例外**：枚举全部非 MCP 入口，恰好是清单上那四个，且每一个都无法创建或修改业务对象。
- **注册骨架的强制性**：构造一个"忘了声明角色"的 tool，**注册失败**——而不是注册成功后在运行时才发现没鉴权。

## 内部工作包建议

一次 **Solid Change**：

```text
WP-A 服务形态 + 认证中间件（令牌 → 身份，接 RP-02）
        │
        ▼
WP-B 注册骨架（schema / 角色 / 幂等 / 留痕 五件一次性固化）
        │
        ▼
WP-C 能力发现按角色裁剪 + 错误契约 + 四个例外清单
```

**WP-B 是本包的全部意义。** 它一旦留了"可以先不声明、以后补"的口子，后面八个包会把这个口子用满。

## 风险与待定

- **最大的风险是"骨架不够用，于是某个包绕过它自己注册"。** 缓解办法是让 RP-04 的表专属 tool 派发**第一个**落在骨架上——那是最不规则的一种 tool，它能落上去，别的都能。
- **`MCP-005` 的派发机制虽然在 RP-04 实现，但它对骨架的要求必须在本包设计时就问清楚**：动态生成的 schema、随建表而增减的 tool 集合、能力发现要跟着变。**这三件在 WP-B 设计时就要问 RP-04 要形状**，不能等它来接的时候再改骨架。
- **本包与 RP-05 的 HTTP 面不要共用路由层。** 一旦共用，"后端不为 Web 暴露写接口"（`BRD-005` ①）就从结构性保证退化成配置正确性。
