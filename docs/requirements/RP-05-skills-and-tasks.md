# RP-05 技能与任务

> 技能资产 · 任务定义 · 手动触发 · 执行调度 · 执行记录与产物 · 视图

## 归属与依赖

- **依赖**：RP-01 平台基座（归属、鉴权、留痕）、RP-02 容器化执行运行时（真正把执行跑起来）。
- **增强来源**：RP-04 代码仓接入——做完之后，技能才多出"能读代码"这项能力。
- **被依赖**：RP-08 自动触发。
- **独立性**：本包与 RP-02 之间只有**一条执行契约**（R-02-01）。契约一定型，两个包可以**并行开发**——本包对着契约写，RP-02 对着契约实现。**RP-04 未就位时本包仍可完整验收**：技能声明自己不需要代码仓（例如"根据缺陷账本生成周报"），链路一样跑得通。

## 背景与价值

这个包覆盖你的第 3、4 条需求：**项目中创建 SKILLS** → **后台运行 AGENT，根据用户的任务执行** → **可以查看任务每次执行的输出**。

它是执行域的**领域层**：技能是"怎么做"，任务是"对什么做、什么时候做"，执行记录是"做完了给谁看"。真正把 Agent 跑起来的那一半在 RP-02。

拆分的接缝选在这里，是因为**领域层与沙箱基础设施的变化速度完全不同**：技能的生命周期、任务的策略会随产品认知反复调整；容器隔离与 dsh 桥接一旦做对就很少动。把它们分开，前者可以快速迭代而不必每次重新验证隔离。

技能是产品的核心价值，也是最大的风险面：

- **价值**：把"我这次是怎么让 AI 做代码检视的"从一次性对话，固化成可重复、可定时、可复用的资产。
- **风险**：技能是**别人写的、会在服务端执行、能读到代码仓**的东西。它比缺陷描述危险得多——缺陷描述只是被读进上下文，技能是主动指挥 Agent 的指令。

因此有一条纪律从一开始就要在：**上传不执行。** 这条防的**不主要是别人，是作者自己**——一份还没试过的技能被自动跑起来，浪费算力，产出没人信的报告。

## 范围

### 包含

- 技能的创建、版本化、生命周期（草稿 → 测试 → 发布 → 停用）
- 任务定义：引用技能、输入参数、目标仓与修订、执行策略
- 手动触发
- 执行的排队、并发控制、重叠策略（**调度**，不是执行本身）
- 执行记录与产物的存储与查询
- 技能视图、任务视图、执行历史与产物视图

### 不包含

- **容器沙箱、进程桥接、隔离**——归 RP-02。本包通过执行契约提交请求，不关心它在哪跑。
- **自动触发**（定时、Git Hook、MCP 触发）——归 RP-08。本包只做手动。
- **代码仓的绑定与工作区准备**——归 RP-04。
- **HTML 产物**——D9 明确推迟。
- **成本约束与额度限制**——D10 明确不做。
- **判断产出质量**——不做（G8）。
- **任务之间的依赖编排**——明确不做，见"风险与待定"。

## 需求条目

### 技能

| ID | 需求 |
|---|---|
| R-05-01 | 技能归属项目，由项目成员通过 MCP 创建（G1）。 |
| R-05-02 | 技能有稳定标识与人类可读名称；名称在项目内唯一。 |
| R-05-03 | 技能内容**版本化且已发布版本不可变**。修改产生新版本。 |
| R-05-04 | 技能声明其**输入契约**：需要哪些参数、类型、是否必填。契约必须是**可机读**的，否则任务无法校验自己提供的输入。 |
| R-05-05 | 技能声明其**产出格式**。MVP 及其后一段时间只支持 Markdown（D9）。 |
| R-05-06 | 技能声明它是否需要**读取代码仓**以及需要哪个绑定。**不声明需要代码仓的技能，执行时不得获得任何工作区**——这一条在 RP-02 的能力清单里兑现。 |
| R-05-07 | 技能声明其**预计执行时长上限**；未声明时用平台默认值。 |
| R-05-08 | 技能状态至少包含：草稿、已发布、已停用。 |
| R-05-09 | **上传不执行。** 草稿状态的技能不会被任何自动触发路径执行。 |
| R-05-10 | 技能必须经过至少一次**成功的测试执行**才能发布。测试执行由作者手动发起，**在与正式执行相同的沙箱中进行**。 |
| R-05-11 | 发布只需项目成员权限，**不经过审批流程**。技能影响的是它自己那份分析与报告，不改变任何团队的 Agent 行为，也不扩大作者本来就有的只读范围。 |
| R-05-12 | 已发布的技能可停用；停用后不再被触发，历史执行记录完整保留。 |
| R-05-13 | 技能内容是**不可信输入**（G7）。平台不解析其语义、不因其内容改变控制流，只负责交给执行运行时。 |

### 任务

| ID | 需求 |
|---|---|
| R-05-14 | 任务归属项目，由项目成员通过 MCP 创建。 |
| R-05-15 | 任务引用一个**已发布**的技能。引用草稿技能被拒绝。 |
| R-05-16 | 任务声明技能版本策略：**固定版本**或**跟随最新发布版**。**默认固定版本**——跟随最新意味着技能作者一次发布会改变所有引用它的任务的行为，这应当是明确选择而不是默认。 |
| R-05-17 | 任务提供的输入参数必须满足技能的输入契约（R-05-04）。不满足时创建失败并指明缺哪个参数。 |
| R-05-18 | 若技能声明需要代码仓，任务必须指定使用项目的哪个绑定及目标修订范围。 |
| R-05-19 | 任务可被启用与停用。停用的任务不响应任何触发，包括手动。 |
| R-05-20 | 任务声明**重叠策略**：上次执行未结束时又被触发，是**跳过本次**、**排队等待**、还是**终止上次并重跑**。**默认跳过**——定时任务最常见的故障是执行变慢后堆积成雪崩。 |
| R-05-21 | 任务声明单次执行的**超时上限**；未声明时用平台默认值。该上限随执行请求传给 RP-02。 |
| R-05-22 | 任务可声明失败重试次数与间隔。**默认不重试**——一个会读代码、调模型、产出报告的任务，盲目重试的代价不小且很少有用。 |

### 手动触发与调度

| ID | 需求 |
|---|---|
| R-05-23 | 项目成员可通过 MCP 手动触发任务，**立即得到执行标识，不阻塞等待完成**。 |
| R-05-24 | 触发前检查：任务存在、已启用、允许手动触发。任一不满足则拒绝并留痕。 |
| R-05-25 | 触发受重叠策略约束（R-05-20）。**被跳过的触发必须留痕**——一个静默被跳过的任务，会让人以为它在跑。 |
| R-05-26 | 每次触发记录触发方式与触发者身份（G5），传递给执行记录。 |
| R-05-27 | 并发执行数有上限，按平台与项目两级控制，防止单个项目耗尽全部算力。 |
| R-05-28 | 装配执行请求时，只把技能实际声明的能力放进能力清单（R-02-02）。**本包不得给出技能没有声明的能力。** |
| R-05-29 | 执行请求中**不放入任何凭据**（R-02-04）。 |

### 执行记录与产物

| ID | 需求 |
|---|---|
| R-05-30 | 每次执行产生一条**独立记录，永不被后续执行覆盖**。 |
| R-05-31 | 执行记录包含：执行标识、所属任务、触发方式与触发者、**实际使用的技能版本**、**代码仓与确切修订**、输入参数、开始/结束时间、最终状态、失败分类。 |
| R-05-32 | 执行记录在其任务被修改或停用后仍完整保留。 |
| R-05-33 | 产物内容一经写入不可修改。需要更正就重新执行。 |
| R-05-34 | 部分完成的执行（超时、取消、失败）已产生的产物仍被保留并可读，且**明确标注该产物来自未正常完成的执行**。 |
| R-05-35 | 产物携带 RP-02 移交时的**不可信内容标注**，这个标注从存储到呈现不得丢失。 |
| R-05-36 | 单次执行的产物有体量上限，超限时截断并**明确标注被截断**，不静默丢弃。 |
| R-05-37 | 保存 RP-02 移交的过程记录，供失败时排查。**过程记录中不得出现任何凭据。** |
| R-05-38 | 执行记录、产物、过程记录三者的保留期可以不同——过程用于排查，结论用于回看，价值衰减速度不同。 |

### 视图（只读）

| ID | 需求 |
|---|---|
| R-05-39 | 技能视图：列表、状态、版本历史与内容。 |
| R-05-40 | 任务视图：列表、状态、配置。 |
| R-05-41 | **执行历史视图：同一任务连续多次执行，按时间倒序，含状态与产物入口。这是"查看任务每次执行的输出"这条需求的直接落点。** |
| R-05-42 | 单次执行详情视图：元数据、产物、过程记录。 |
| R-05-43 | **Markdown 产物渲染时禁用内联 HTML 与脚本**，只渲染受限标记子集；外部资源引用被明确标注为外部且不自动加载。 |
| R-05-44 | 提供产物的原始形式下载，供不信任渲染的人自行查看。 |
| R-05-45 | 视图上不存在任何写入操作（G2）。 |

## 数据与不变量

- **I-05-1**：已发布的技能版本不可变；未经测试执行的技能不可发布。
- **I-05-2**：执行记录与产物一经写入不可变，且永不因任务变更而丢失。
- **I-05-3**：每次执行都能追溯到确切的技能版本与代码修订。
- **I-05-4**：产物在系统内始终携带"不可信内容"标记。
- **I-05-5**：执行请求的能力清单是技能声明的子集，**本包不扩权**。

## 验收标准

- 创建技能后状态为草稿；草稿技能无法被触发。
- 未经测试执行直接发布被拒绝；完成一次测试执行后发布成功。
- 发布 v1 后修改产生 v2，v1 内容不变，已有执行记录仍指向 v1。
- 引用草稿技能创建任务被拒绝；缺少契约必填参数时创建失败并指明缺哪个。
- 技能声明需要代码仓但任务未指定绑定时，创建失败。
- 停用任务后手动触发无效。
- 手动触发返回执行标识且**不阻塞**；上次未结束时的触发按重叠策略被跳过且留痕。
- **检查提交给 RP-02 的执行请求：能力清单不超出技能声明，且不含任何凭据。**
- 同一任务连续执行五次，五条记录全部保留，产物互不覆盖。
- 修改任务配置后，此前五条记录的元数据仍是当时的值。
- 超时的执行状态为已超时、部分产物可读且带"未正常完成"标注。
- 产物超过体量上限时被截断并标注。
- 检查过程记录：**不含任何凭据原文**。
- **构造一份含恶意内容的 Markdown 产物**（内联脚本、事件处理属性、外部资源引用），在 Web 上打开：**脚本不执行、外部资源不自动加载、会话不泄露**。这条必须实际构造并验证，不能只做代码审查。

## MVP 子集

**以裁剪后的子集纳入 MVP。**

MVP 做到：
- 技能：创建、可机读输入契约、产出格式、是否需代码仓、**草稿/已发布两态**、发布前必须测试执行成功、版本化
- 任务：引用已发布技能（**仅固定版本**）、输入参数、指定仓与修订、启停
- 手动触发（非阻塞 + 重叠策略默认跳过）
- 执行记录：每次一条永不覆盖、完整元数据、Markdown 产物、过程记录
- 视图：技能列表、任务列表、**执行历史列表**、单次执行详情与安全 Markdown 渲染

MVP 可推迟：技能停用（R-05-12）、资源预期声明（R-05-07）、跟随最新版本策略、重试（R-05-22）、排队与终止重跑两种重叠策略、项目级并发配额（R-05-27 先做平台级）、多产物、保留期与清理（R-05-38）。

**不可裁剪**：R-05-09（上传不执行）、R-05-10（发布前必须测试过）、R-05-13、R-05-15、R-05-17、R-05-23（非阻塞）、R-05-25（跳过留痕）、**R-05-28／R-05-29（不扩权、不放凭据）**、R-05-30～R-05-32、R-05-35、R-05-37、**R-05-43（禁用内联 HTML）**。

关于 R-05-43 特别提醒：**绝大多数 Markdown 渲染库默认开启内联 HTML。** MVP 只有 Markdown 产物，很容易顺手用默认配置就上线。而产物内容部分来自被分析的代码仓——**能往那个仓提交代码的人，就能影响产物内容**。这是产物渲染这条攻击链上唯一的那道门。

## 内部工作包建议

```text
WP-A 技能资产（创建、版本化、生命周期状态、声明契约）
        │
        ├──► WP-B 任务定义（引用技能、参数校验、执行策略）
        │            │
        │            ▼
        │       WP-C 触发与调度（非阻塞、重叠策略、并发控制、请求装配）
        │            │
        │            ▼
        │       WP-D 执行记录与产物存储
        │            │
        └────────────┴──► WP-E 只读视图（含安全 Markdown 渲染）
```

**WP-C 是本包与 RP-02 的对接点**，它依赖执行契约（RP-02 的 WP-A）已定型，但不依赖 RP-02 的实现完成——可以先对着桩实现开发。

## 风险与待定

- **技能的内容形态未定**（Markdown 提示词、结构化步骤定义、还是某种 dsh 可识别的资产形式）。这与 RP-02 的桥接实现相关，属于设计选型。需求侧唯一的硬约束是 R-05-04：**输入契约必须可机读**。

- **R-05-10 里的"测试执行成功"怎么判定？** 技能执行完成不代表结果有用。建议 MVP 只要求"执行完成且未报错"，由作者自己看产出决定是否发布——**不要试图自动判断产出质量**，那是判断题（G8）。

- **任务编排明确不做。** 一旦支持"任务 A 完成后触发任务 B"，就需要 DAG、依赖解析、失败传播、循环检测及其可视化——这正是"不长成平台"那条边界要拦住的东西。需要串联就在一个技能内部完成多步。**建议写死。**

- **执行历史的对比视图不做。** "怎么对比两次报告"依赖产物结构，而产物是自由文本。**想要趋势就写一个读取历史执行结果的技能**，让它自己产出趋势报告。平台提供机制，不规定内容。

- **删除任务的语义**：I-05-2 要求执行记录不丢，所以"删除"实际只能是停用+隐藏。**建议不提供删除，只提供停用**——少一个会让人误以为数据没了的操作。
