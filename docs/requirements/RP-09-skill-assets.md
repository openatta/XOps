# RP-09 技能资产

> 内容与版本 · 上传不执行 · 发布前必须测试执行 · 公共与私有

## 归属与依赖

- **依赖**：RP-03 MCP 基座、RP-02 身份与项目（归属判定）。
- **被依赖**：RP-10 任务与执行策略（任务引用一个已发布的技能）。
- **里程碑**：M2。
- **独立性**：技能是一份**资产**——内容、版本、生命周期、归属、声明。**它不需要能跑起来就能验收**（见风险一节对 `SKL-003/004` 的说明）。

## Crate 归属

| crate | 本包是否新建 | 对外只经什么被用 |
|---|---|---|
| `xops-skill` | **新建** | 技能的读写 · 版本解析 · **声明的读取**（输入契约 / 数据源 / 出网 / 时长）· 归属判定 |

> **本包是 `xops-skill` 唯一的动刀方。** 上一版这三个包挤在一个 `xops-task` 里，导致 RP-09 → RP-12 → RP-13 要串成一条三节的链；拆成三个 crate 之后，本包与 RP-10 只经接口相见，**能重叠开工**。

## 背景与价值

技能是产品核心价值的载体：

> **把"我这次是怎么让 AI 做代码检视的"，从一次性对话固化成可重复、可定时、可复用的资产。**

它也是**最大的风险面**——它是**别人写的、会在服务端执行、能读到代码仓**的东西。所以两条纪律从第一天就要在，而且都落在本包：

| 纪律 | 防的是什么 |
|---|---|
| **`SKL-004` 上传不执行** | **这条防的不主要是别人，是作者自己。** 创建一个技能不产生任何执行——否则"写一半存一下"就会真的跑起来 |
| **`SKL-005` 声明即边界** | 一次执行的可见范围**完全由技能的声明决定**（`I-I`）。声明写在本包，装配派工单的人（RP-11）只能照着它放，不能扩 |

**两种归属**是本包另一半内容：

```text
项目公共  ── 归项目所有，项目成员都能看、能用、能触发
个人私有  ── 归创建它的人所有，同项目的其他成员看不到、也用不了
           但它**在项目中执行，用项目的数据源**
```

**私有技能能读项目数据，是因为它的所有者是项目成员。权限来自人，不来自技能**——一个人退出项目，他挂在这个项目里的私有任务立刻失去数据源。

**一条例外要写死**：一旦某个私有技能的某个版本被用于满足某个流程节点，**该版本的内容对项目成员转为可读**。**私有是为了不打扰别人，不是为了让自动决策不可审查。**

## 范围

### 包含

- 技能的内容与**版本**（已发布版本不可变）
- **上传不执行**
- 生命周期：草稿 / 发布 / 停用；**发布前必须有一次成功的测试执行**
- **声明**：输入契约 · 数据源 · 出网 · 时长
- **两种归属**：项目公共 / 个人私有；**从公共派生私有副本**
- 私有技能被用于流程节点后**转为项目内可读**这条例外
- 内容与版本历史的查询

### 明确不包含

- **任务**——归 RP-10。技能是资产，任务是"什么时候用它、用完写哪"。
- **测试执行的发起与承载**——`SKL-003` 的**门**在本包（没有成功测试就不能发布），**产生那次执行的链路在 RP-11**。见风险一节。
- **派工单装配**——归 RP-11。本包只提供声明，不组装。
- **跨项目复制技能**——**Q14** 未定，目前不允许（`SKL-012`）。

## 关键不变量

`I-C`（每个对象恰好有一个归属方）· `I-I`（可见范围完全由声明决定）· `I-K`（已发布的技能版本不可变；**未经成功测试执行的技能不可发布**）· `G4`（权限按项目判定）。

## 接口面

**MCP tools**：创建 / 更新（产生新版本）· **发起测试执行** · 发布 / 停用 · 查询内容与版本历史 · 声明归属 · 派生私有副本。

> **「发起测试执行」这个 tool 注册在本包，链路在 RP-11。** 本包持有的是"这个版本有没有一次成功的测试执行"这个事实与它的门。

**对内提供给 RP-10 / RP-11**：

```text
resolve(skill, version) -> 内容 + 声明 + 归属 + 是否已发布
```

## 验收标准

- **上传不执行**：创建一个技能**不产生任何执行**（枚举代码路径，创建路径上没有任何提交执行的调用）。
- **未经成功测试执行不可发布**：直接发布一个从未测试过的版本，**被拒绝**。⚠️ 这条可用一条**伪造的成功测试执行记录**验收，**不需要 RP-11 已完成**。
- **已发布版本不可变**：改内容产生新版本；旧版本原样可查。
- **声明是穷举的**：输入契约、数据源、出网、时长——四样都能声明，**且声明之外没有第五条获取能力的途径**。
- **私有可见性**：同项目其他成员**看不到、也用不了**一个私有技能。
- **退出项目即失效**：一个人退出项目后，他名下的私有技能**不能再被用于该项目的执行**。
- **派生**：从公共技能派生一份私有副本，是**一次拷贝而不是引用**——改私有副本不影响公共的。
- **例外转为可读**：把某个私有技能版本标记为"已用于满足某流程节点"，该版本内容对项目成员**转为可读**（本包按这个标记实现，标记由 RP-15 打）。
- **跨项目复用被拒绝**（`SKL-012`，Q14 未定之前）。

## 内部工作包建议

一次 **Solid Change**：

```text
WP-A 技能内容与版本（上传不执行、版本不可变、内容与历史查询）
        │
        ├──► WP-B 声明（输入契约 / 数据源 / 出网 / 时长）
        │
        └──► WP-C 归属（公共 / 私有 / 派生 / 退出即失效 / 被用于节点后转可读）
                    + 生命周期与发布门
```

## 风险与待定

- **`SKL-003`「发布前必须测试执行」跨了本包与 RP-11。** 本包持有**门**（没有成功测试记录就不能发布），RP-11 持有**产生那次记录的链路**。**验收时用伪造记录验门**，不要因此把本包排到 RP-11 之后——那会重新串起一条链，正是这次拆分要消掉的东西。
- **Q14（跨项目复制技能）**未定，不阻塞。目前 `SKL-012` 是"不允许"，理由是它会引出平台级权限，与 G4 冲突。
- **"被用于流程节点后转为可读"这条例外的触发点在 RP-15**（结算时打标记）。**本包要先把这个标记位与它的可见性效果做出来**，否则 RP-15 接进来时没有地方可打。
