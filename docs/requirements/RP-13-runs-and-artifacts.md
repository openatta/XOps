# RP-13 执行记录与产物

## 归属与依赖

- **依赖**：RP-12（产生记录与产物）、RP-11（记录归属任务）、RP-02（访问控制）。
- **被依赖**：RP-15（呈现）、RP-16（执行完成通知）。
- **不做这个包会阻塞谁**：你的第 4 条需求后半句——"可以查看任务每次执行的输出"。

## 背景与价值

你的原话：**输出 MD 或 HTML 数据，可以查看任务每次执行的输出。**

"每次"这个词是这个包存在的全部理由。如果只保留最新一次结果，这个平台就退化成一个报告生成器；保留每一次，它才是**质量监控**——质量看的是趋势与系统性偏差，不是某一次的结论。

一份代码检视报告单独看价值有限，但"同一个技能对同一个仓连续跑三十天"能回答一些单次报告回答不了的问题：这个问题是新出现的还是一直都在、上次的修改有没有让指标变好、哪些告警是长期噪音。

把它从 RP-04 审计日志里分出来，是因为两者性质完全不同：

| | 审计事件（RP-04） | 执行产物（本包） |
|---|---|---|
| 体量 | 小、结构化 | 大、非结构化 |
| 保留期 | 长（合规性质） | 可较短 |
| 访问频率 | 低 | 中 |
| 可信度 | 确定性代码产生 | **模型产生，不可信** |

把大体量的模型产出塞进追加式审计事件流，会把审计日志拖垮，而且会让"审计事件"这个概念混入不可信内容。

## 范围

### 包含

- 执行记录的存储与查询（每次执行一条，永不覆盖）
- 产物（Markdown / HTML）的存储与读取
- 过程记录（步骤、工具调用、耗时、原始输出）
- 同一任务多次执行的历史与对比入口
- 保留期与容量策略
- 产物的安全呈现约定

### 不包含

- **执行本身**——归 RP-12。
- **产物的渲染**——归 RP-15，本包只负责存与取，以及声明内容不可信。
- **对产物内容做分析、摘要、评分**——不做（G8）。
- **跨项目的横向报表**——不做。这类需求应当由一个技能去读多次执行结果来完成，而不是由平台内建报表引擎。

## 需求条目

### 记录

| ID | 需求 |
|---|---|
| R-13-01 | 每次执行产生一条独立记录，**永不被后续执行覆盖**。 |
| R-13-02 | 执行记录包含：执行标识、所属任务、触发方式与触发者、实际使用的技能版本、代码仓与确切修订、输入参数、开始/结束时间、最终状态、失败分类（继承 R-12-18）。 |
| R-13-03 | 执行记录在其任务被修改或停用后仍完整保留（I-11-4）。 |
| R-13-04 | 支持按任务、时间范围、状态、触发方式查询执行历史。 |
| R-13-05 | 提供同一任务连续多次执行的列表视图，按时间倒序，含状态与产物入口——**这是"查看每次执行的输出"这条需求的直接落点**。 |

### 产物

| ID | 需求 |
|---|---|
| R-13-06 | 支持存储 Markdown 与 HTML 两种产物格式（R-10-05）。 |
| R-13-07 | 一次执行可以产生多个产物（例如一份主报告加若干附表）。 |
| R-13-08 | 产物内容一经写入不可修改。需要更正就重新执行。 |
| R-13-09 | 部分完成的执行（超时、取消、失败）已产生的产物仍被保留并可读（R-12-11、R-12-12），且**明确标注该产物来自未正常完成的执行**。 |
| R-13-10 | 产物被标注为**不可信内容**（R-12-17）。任何消费方（尤其 RP-15）必须按不可信内容处理。 |
| R-13-11 | 单次执行的产物有体量上限，超限时截断并明确标注被截断，**不静默丢弃**。 |

### 过程记录

| ID | 需求 |
|---|---|
| R-13-12 | 保留执行的过程记录，至少包含原始输出流，供失败时排查。 |
| R-13-13 | 过程记录中不得出现任何凭据（继承 I-12-2）。 |
| R-13-14 | 过程记录的保留期可以短于执行记录本身——过程用于排查，结论用于回看，两者的价值衰减速度不同。 |

### 访问与保留

| ID | 需求 |
|---|---|
| R-13-15 | 执行记录与产物的访问遵循项目成员边界（R-02-07）。非成员查询返回与不存在一致的结果。 |
| R-13-16 | 保留期可配置：执行记录、产物、过程记录三者可以有不同的保留期。 |
| R-13-17 | 达到容量上限时按最旧优先清理，且清理产生审计事件——**产物消失必须是可解释的**。 |

## 数据与不变量

- **I-13-1**：执行记录与产物一经写入不可变。
- **I-13-2**：执行记录永不因任务变更而丢失或被改写。
- **I-13-3**：产物在系统内始终携带"不可信内容"的标记，从存储到呈现不丢失。
- **I-13-4**：过程记录中不含凭据。

## 接口面

**MCP tools**

| 意图 | 说明 |
|---|---|
| 查询任务的执行历史 | 分页，按时间倒序 |
| 查询单次执行详情 | 含元数据与产物列表 |
| 读取产物内容 | 按产物标识 |
| 查询执行的过程记录 | 排查用 |

**只读查询面**（供 RP-15）

- 任务的执行历史列表
- 单次执行详情与产物渲染
- 过程记录

## 验收标准

- 同一任务连续执行五次，五条记录全部保留，各自的产物互不覆盖。
- 修改任务配置后，此前五条记录的元数据（技能版本、参数）仍是当时的值。
- 停用任务后，历史执行记录仍可完整查询。
- 超时的执行，其部分产物可读且带有"未正常完成"标注。
- 产物超过体量上限时被截断并标注，可读部分完整。
- 检查过程记录：不含任何凭据原文。
- 非项目成员查询执行记录，返回与不存在一致的结果。
- 触发保留期清理后，产生了可查的审计事件。

## MVP 子集

**以裁剪后的子集纳入 MVP。**

MVP 做到：
- 每次执行一条记录、永不覆盖（R-13-01）
- 记录完整元数据（R-13-02）
- 存储 Markdown 产物（HTML 随 RP-12 一起推迟）
- 任务的执行历史列表（R-13-05）——**这是 MVP 要验证的用户价值本身**
- 保留原始输出作为过程记录（R-13-12）
- 不可信内容标注（R-13-10）

MVP 可推迟：
- 多产物（R-13-07，先支持单产物）
- 保留期与清理（R-13-16、R-13-17，MVP 无限保留）
- 过程记录的独立保留期（R-13-14）
- 体量上限（R-13-11）——但**要有一个粗暴的硬上限防止单次执行写爆存储**

**不可裁剪**：R-13-01、R-13-02、R-13-03、R-13-10、R-13-13、R-13-15。

## 风险与待定

- **R-13-10 的不可信标注是这个包最容易被忽略、后果最严重的一条。** 产物是模型生成的 HTML，会被渲染进 Web 页面（RP-15）。如果直接渲染，一份产物里的脚本就能在查看者的浏览器里以查看者的身份行动——而产物内容部分来自被分析的代码仓，也就是说**攻击面一路延伸到"谁能往被分析的仓里提交代码"**。这条约束必须在 RP-15 兑现，本包负责让标注不丢失。

- **HTML 产物是否值得支持**需要重新掂量。Markdown 渲染的安全边界清晰得多（可以只允许一个受限子集）。HTML 产物的价值主要是图表与排版，但代价是上面那条风险。**建议：MVP 只做 Markdown，等确实出现 Markdown 表达不了的需求，再连同沙箱化渲染方案（如隔离 iframe）一起讨论 HTML。**

- **执行历史的对比视图**（R-13-05 提到的"趋势"）没有写成需求条目，因为"怎么对比两次报告"依赖产物的结构，而产物是自由文本。**建议不做内建对比**——想要趋势就写一个读取历史执行结果的技能，让它自己产出趋势报告。这符合"平台提供机制，不规定内容"的边界。

- **产物存储的位置与形态**（数据库、对象存储、文件系统）属于设计选型，不在需求阶段决定。需求侧唯一的约束是 R-13-08 的不可变与 R-13-11 的体量上限。
