# 用使用者的方式跑一遍

这里的东西**全程经 MCP**。除了签第一把令牌（`xopsd --issue-token`，它只能是一条命令，
见 `docs/contracts/rust.md` 的 `Directory::bootstrap_token`），没有一处走内部接口。

和 `crates/*/tests/` 的分工：

```
crates/*/tests/     单元与包验收 —— 证明每一件东西自己是对的
scenarios/          场景 —— 证明它们接起来之后还是对的，而且是从外面看
```

**这个目录存在的理由是一类具体的缺陷**：单元全绿、装配也过，但那条链在运行时是断的。
上一轮一口气撞出七处这样的注入位，再上一轮三处，写这几个场景时又撞出两处
（`WorkspaceSource` 一处实现都没有 · `TestRuns` 没接工作区），
跑一个"分析代码仓、给出简介"的真用例时又撞出一处（**引擎手上一件工具都没有**）。
它们的共同点是**不报错**——没有人调用的代码不会喊。
从外面按使用者的顺序走一遍，是唯一能看见它们的办法。

## 怎么跑

```bash
scenarios/run.sh              # 三个场景都跑
scenarios/run.sh 01 03        # 只跑其中几个
```

要一份 `.env`（或直接给环境变量）：

```
XOPS_MODEL_KEY        模型 API key。**没有它就没法跑**——场景里有真的模型调用
XOPS_MODEL_BASE_URL   模型服务地址（兼容 Anthropic Messages 的任何一个）
XOPS_MODEL            模型名
```

跑完什么都不留：库、工作区、本地仓都在一个 `mktemp -d` 出来的目录里，退出时删掉。
**不放在 `/tmp` 的固定路径下**——外部清理会整批抹掉它（踩过，一次抹掉 19 个工作树）。

## 三个场景

### 01 · 任务（`01-任务.sh`，18 条）

使用者的六步，代码仓那步在 02：

```
建项目 → 建技能 → 试跑 → 发布 → 建任务 → 触发 → 看结果
```

盯的是几件**只有真跑才看得见**的事：

| 断言 | 断掉会怎样 |
|---|---|
| `SKL-003` 没测过发不了 | "上传即可用" |
| `EXE-021` 触发立刻返回 | 调用方被阻塞在一次模型调用上 |
| **落账**：`_runs` 上有那一行 | **执行成功了，账上什么也没有** |
| `EXE-022` 过程记录不是一串 `event` | 出事时那份记录一个字也没说 |
| `EXE-027` 连开 8 次进 4 挡 4 | 一个项目吃掉全部算力 |
| 落账之后名额还回来 | 第一批跑完之后再也接不了活 |

### 02 · 代码仓（`02-代码仓.sh`，22 条）

本地仓（`file://`），全程不出网。

```
造 bare 仓 → 推一笔 → 设成只读 → repo.bind → 建 needsRepository 的技能
     → 试跑 → 看工作目录 → 让它 Glob + Read 读仓里的文件
```

⚠️ **重点是最后一段：执行的工作目录是不是那份工作区。**
备好的工作区曾经根本没交给引擎——`D61` 把引擎搬进程时，两进程那版传 `project_root`
的那一步没跟过来，于是 agent 在 xopsd 自己的 cwd 里跑、读 XOps 的源码。
**它读到了东西，只是读错了地方，而且不报错。**「读错了地方」和「读不到」是两件事，
后者会喊，前者不会。

另外两件在这里被证明的事：

- **本地仓的只读证明是问操作系统，不是推一次。** 实测：`git push --dry-run` 走
  `file://` 时，目标目录只读也返回 0——远端那条路在本地是**静默失效**的。
  见 `crates/xops-repo/src/local.rs` 的模块注释。
- **本地仓没有凭据。** `repo.bind` 的 `credential` 对 `file://` 必须不给：
  往一个专放密钥的字段里塞占位串，`repo.rotate` 会把那串垃圾当真凭据去换。

**这一段撞出的两处**，都是「不报错」型:

- **备好的工作区没交给引擎**（`D61` 搬进程时落下的那根线）。
- **引擎手上一件工具都没有。** `Builder` 拿不到注册表时用一个空的
  `InMemoryToolRegistry`，于是每次请求里的 `tools` 是 `[]`。症状不是"工具调用失败"，
  是模型**用自己的方式凑合**——把工具调用当文本吐出来
  （`<｜｜DSML｜｜invoke name="Read">…`），或者绕道解释"我没有 shell 工具"。
  **一次执行看着是成功的，产出里一个字有用的都没有。**
  装上之后由场景的白名单收窄到只读那三样（`I-I`）。

⑥ 那一段现在真的让技能 `Glob` + `Read` 读仓里的文件，并且断言
**产出里没有 `DSML`、也没有引擎的回合旁白**——两样都是上面那两处的症状。

⑦ **越界读不出去**（`EXE-012` / `I-I`）。这条也是实测撞出来的:
引擎的 `Builder` 拿不到 `Permission` 时用 `AllowAll`，而工具那一侧对越界路径
回的是"要人确认"——**无人值守的执行里没有人可问**，"要确认"就这么退化成了"随便读"。
技能当时读到了工作区之外的文件。**默认值站在哪一边，是这类洞唯一的成因。**

⑧ **产出行落进声明的那张表**（`EXE-031`）。技能调 `EmitRow` 交回行，
参数形状是**按目标表的列生成的**——模型看见真的列名，不用猜。
试跑**收得下行但不落表**（试跑没有任务，也就没有 `writes`）；
正式触发那条落表，行上署的是那次执行（`TBL-016`）。

### 03 · 流程（`03-流程.sh`，22 条）

一条**全程经 MCP 定义**的两步流程，第二步是并行组。**一次模型调用都没有**，
所以它跑得快，该是回归里跑得最勤的那一个。

```
建表 → flow.define → flow.start → 甲自批（不算数）→ 乙表态（推进）
     → 并行组两个节点各自结算 → approved → 另起一个实例一票拒绝 → flow.disable
```

盯的是：

- `FLW-001` 流程定义经 MCP 创建。这条以前是断的——能到 `Flows::define` 的
  只有 `template.instantiate` 那一条路。
- `FLW-008`③ 筛选证不出互斥就拒绝定义。**宁可误拒**：误放的后果是运行时
  一行同时结算两个节点，而那是事后查不出来的。
- `MCP-004` 打错一个键名要被拒，而且指得出在哪一层（`steps[0][0]`）。
  这里最怕被静默丢掉的是 `separationOfDuties`——**少了它没有任何症状，
  只是审批不再需要第二个人**。
- `FLW-026`③ 职责分离：发起人自己表态不算数。它验的是"定义参数里那个
  `separationOfDuties` 真的走到了求值那一侧"。
- `FLW-027` 不算数的行**照常留在表里**，只是不结算，而且写的人收到通知。
- `FLW-002` 并行组：两个节点同时激活，全部通过才推进。
- `FLW-034` 一票拒绝让整个实例立即进终态。
- `FLW-006` 停用之后发不起新实例，在途的继续走完。

## 依赖模型的那几条，怎么处理

⑥ 和 ⑧ 靠模型真的去调工具。它**不是每次都听话**——实测同一条断言 3 遍里红 1 遍，
而同一遍里正式触发那条是通过的:**链路是好的，只是那一次模型没调**。

`"经常红但不用管"的测试等于没有测试`——下次真断了也会被当成又一次模型抽风。
所以这几条**最多重试 3 次，而且每一次重试都打出来**：

```
   ↻ 模型这次只交回 0 行（第 1 次）
   ↻ 模型这次只交回 0 行（第 2 次）
   ✗ 试跑收得下行
```

链断 = 连红到用光次数，**照样红**；模型抽了 = 那行 `↻` 出现在输出里，
人一眼看得见"它试了几次才过"。

⚠️ ⑧ 数的是「**这一次执行**落了几行」，不是表里一共几行:
重试会再触发一次，而行是追加的（`TBL-012`）——按 run 数才不会把两次的加在一起，
也才说得上"某一次执行把它交回的行全落下来了"。**这同时就是 `TBL-016` 的署名断言。**

⚠️ **重试这条路本身要被验过。** 它平时不跑，正是这一版反复撞到的那类
"没有人调用的代码不会喊"——验法是把技能内容改成"不要调用任何工具"跑一遍，
看 `↻` 打不打得出来、用光之后红不红。

## 写场景脚本要知道的两件事

**① 变量名一律 ASCII。** macOS 自带 bash 3.2 不认多字节变量名——`根=x` 会被当成
一条命令（`command not found`）。**函数名它认**，所以断言那一侧留中文：
`要` / `含` / `不含` / `节` / `取` / `收工`，那里才是要读的地方。

**② 带转义双引号的 JSON，先赋值给变量再用。**

```bash
ARGS="{\"project\":\"$PROJ\",\"role\":\"member\"}"
R=$(甲 member.set "$ARGS")          # ✅
R=$(甲 member.set "{\"project\":\"$PROJ\"}")   # ✅ 赋值形式也没问题
含 "..." "$(甲 member.set "{\"project\":\"$PROJ\"}")" "x"   # ❌ 会被切开
```

bash 3.2 在 `cmd "$(f "{\"k\":\"v\"}")"` 这种写法里丢掉引号上下文，
把参数从逗号处切开，于是 `{"project":"01AAA"` 这样半截的 JSON 被发出去，
服务端回"请求体不是 JSON"，而调用点看着完全正常。**踩过一次。**

断言写成一句能读的话，失败时把整个回话打出来——
**场景失败最贵的成本是"不知道它为什么失败"**，而它们跑在一个已经起来的进程上，
没法像单元测试那样贴一段 backtrace。
