# 项目宪法

## 使命与边界

交付项目声明的行为，不得静默扩大范围、权限、数据收集或依赖。

## 架构原则

优先选择小而可测试的模块和明确的契约。除非有已批准的 Change 另行说明，
否则保持现有项目结构和兼容性。

## 安全、隐私与合规

遵循最小权限原则，不把密钥留在仓库资产或输出中，校验所有信任边界输入，
并显式记录安全/隐私影响。

## 质量与可观测性

对外可观察的需求需要自动化验证。失败必须可诊断，且不暴露敏感数据。
没有当前 mandatory gates 的证据，任何 Change 都不算完成。

## 并行研发

只并行化依赖已就绪、且写入路径互不重叠、共享资源可被隔离的工作包。
每个具备写权限的 Worker 使用指定的 worktree 和固定的 base commit，
同一时刻每条路径只有一个写入者。共享契约、迁移脚本、生成文件和锁文件
由唯一的 Integrator 写入。只接受来自已验证 Git diff、声明的验证命令和
当前 Gate Evidence 的交付；Agent 的自然语言描述不构成证明。任何 Agent
都不能自我批准例外。

## 兼容性与版本管理

公开接口、存储数据和协议的变更必须是审慎的，并附带记录在案的迁移与
回滚策略。

## 治理

本宪法优先级高于普通 Rule。修订宪法须经过独立评审的 Change，并更新其
语义化版本号：破坏性原则变更用 MAJOR，新增或实质性扩大原则用 MINOR，
澄清性修改用 PATCH。批准只能由人类或经授权的外部系统给出；AI Agent
不能自我批准例外。
